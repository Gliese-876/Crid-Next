# 正式发行

首个公开开源版本为 `2.0.0`，Android versionCode 为 `30`。此前的 `1.2.0` 是本地首个正式签名版。后续发行应提高 versionCode，并继续使用同一把正式签名私钥。

## 构建

在 Windows PowerShell 中运行：

```powershell
./tools/release.ps1
```

先提交待发布的源码。脚本要求工作区干净，使用本地 JDK 21 与 Android SDK，执行核心和 Release 单元测试、Release lint、APK 与 AAB 构建，并验证 APK 的签名和 ZIP 对齐。生成的 APK 可直接安装；AAB 用于应用商店分发，不能直接安装到设备。

1.15.2 恢复 ARM64、ARM32、x86 和 x86_64 支持。发布脚本直接读取 APK 与 AAB 内的原生库，检查架构路径与 ELF 文件头是否匹配，并核对两种产物的架构集合。发行清单记录架构及库路径，保留原有签名、证书和 16 KB 对齐校验。

正式构建启用 R8 代码优化和资源缩减，使用 Android 默认优化规则及依赖附带的保留规则。项目专用规则位于 `app/proguard-rules.pro`。每次发行保存 `r8-mapping.txt`，其哈希与 APK 一起记入发行清单；分析崩溃时使用对应版本的映射。优化后的正式 APK 应直接验证导入、保存与导出，以及小组件和后台任务等入口。[Android 官方优化说明](https://developer.android.com/topic/performance/app-optimization/enable-app-optimization)

`artifacts/releases/v2.0.0/` 保存本次产物、对应源码、校验值、公开证书指纹与构建记录；后续版本使用相应版本目录。该目录不进入 Git。正式发布前还应在专用测试设备上验证签名后的安装包；既有 Debug 设备测试的结果不能代替 Release 实包检查。

## 签名保管

首发使用专用于 Crid Next 的 PKCS12 签名文件，保存在被 Git 忽略的 `tools/local/signing/`。密码只以当前 Windows 用户的 DPAPI 密文保存，构建时临时传给签名工具。公开证书指纹固定在 `gradle/release-certificate.sha256`；签名材料缺失或证书不符时，脚本会停止并要求恢复原件。脚本不读取 `.env`，也不使用 Debug 证书签名。

签名私钥决定后续版本能否覆盖升级，必须长期保留。DPAPI 密文依赖原 Windows 用户与系统环境，单独把该目录复制到另一台电脑不保证可解密；迁移电脑前应在原环境中完成安全的私钥与密码迁移。不要把私钥或密码作为发行附件、提交到 Git，或写入发布说明。

Gradle 也支持通过 `CRID_RELEASE_STORE_FILE`、`CRID_RELEASE_STORE_PASSWORD`、`CRID_RELEASE_KEY_ALIAS`、`CRID_RELEASE_KEY_PASSWORD` 环境变量使用已有签名；这些变量应由本机安全存储或 CI 的秘密管理功能提供。

## 安装与升级

正式版与此前 Debug 版签名不同，不能直接覆盖安装。先从 Debug 版导出 Crid Next 数据文件并确认保存，再卸载 Debug、安装正式 APK，最后导入数据。卸载会清除应用数据，PNG/PDF 不能恢复课表；学期、作息和个人设置需要重新配置。

本地验证使用专用 QA 模拟器，保留主模拟器上的开发版与用户数据。后续正式版本使用相同证书且不降低 versionCode 时，可覆盖升级已安装的正式版。

## 发行内容与版本标签

分发 APK 时同时提供同一提交的应用源码 ZIP、完整第三方许可声明、MIT 许可、JExcelAPI 完整源码及 `REBUILDING.md`。脚本会生成这些附件、发行清单和 `SHA256SUMS`；构建日志留在本地，不在公开校验清单中。替换 JExcelAPI 和重新构建的步骤见 [重建说明](REBUILDING.md)。第三方组件的许可不随应用改为 MIT。

公开版本使用带说明的 Git 标签 `v2.0.0` 固定源码。GitHub 和 Gitee 使用同一份代码、标签和安装包。脚本只生成本地发行文件；在线 Release 单独创建并上传经过核验的发行附件。

公开仓库由匿名化后的文件树建立，全新初始提交不携带早期含真实测试文件的本地历史。不要将保留私有开发历史的仓库直接镜像或推送到公开远程。
