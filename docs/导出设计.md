# 可视化导出

本文说明 2.0.0 的导出契约。`TimetableExporter` 使用 Android Canvas 排版，PNG 的 Bitmap Canvas 与 PDF 的 PdfDocument Canvas 共用页模型、尺寸和绘制函数。每个选中日、周、月或学期生成一页：日页采用今天页的单列日程，其他页面采用课表页的周网格，并跟随应用浅深主题。PDF 使用内容画布尺寸，PNG 的 1、2、3 倍分辨率仅改变采样。

可视化文件展示课程图表，待排课程在页首汇总数量。完整源授课记录、备注和学分通过当前方案的 JSON 数据文件导出，图表下方不再附加课程列表。

## 入口与范围

`ExportRequest` 接收学期及其方案、应用设置与节假日数据，并指定 `view`、`from`、`to`、`format` 和 `pngScale`。`ExportUnits` 按视图将范围整理成完整日历单位，首尾单位都包含在内。

| 视图 | 范围选择 | 页面单位 |
| --- | --- | --- |
| 日 | 起止日期 | 每天一页，按时段排列的单列日程 |
| 周 | 目标学期的起止教学周 | 每周一页，七列时间课表 |
| 月 | 起止月份 | 每月一页，拼贴该月涉及的周课表 |
| 学期 | 一个或多个学期，每学期选择一个方案 | 每学期一页，拼贴该学期的周课表 |

周次依据学期起始日所在自然周计算，一周起始日跟随应用设置。周视图覆盖完整自然周，月视图覆盖完整月份；超出目标学期的日期留空，月页中相邻月份的日期也留空。学期页使用该学期的完整起止日期。多学期选择按学期日期排序，缺少方案的学期须先指定方案。

日期和时间使用 Material 选择器，月份与教学周使用 Android `NumberPicker`。界面按当前视图展示相应选择器，导出前显示 PDF 页数或 PNG 文件数。数据文件导出仍只处理当前方案，不使用可视化导出的多学期页面模型。

## 课程数据与展示投影

导出为所选方案创建一次 `ScheduleEngine.prepare` 快照，并按日期查询课程。界面和导出共用周次、节假日及调休规则。同名课程沿用归一化身份和持久化 `Course.color`；颜色缺失时使用 `CourseColors.colorFor`。

`displayCourses` 将同一日期、同一时段的同名记录合成展示卡片。同一授课上下文的相邻节次可合成连续课程，跨度包含内部课间；教师、地点、周次或状态不同的记录仍保留各自的数据。其他周记录与本周同名课程相交且周次互斥时，可并入展示，卡片位置、时长及显示字段由代表记录确定。

合并卡片呈现与应用主视图一致的摘要。同一课程在其他周的教师、地点或独立节次记录，不再通过页底列表重复展开；这些源记录仍保存在方案中，并随 JSON 数据文件导出。

## 日页：单列日程

日页与今天页一样，仅展示 `isActual` 的课程；休假停课和非本周记录不进入日程。调休补课按映射后的教学日期与周次计算。

日期统一使用 `UiText.date` 格式，在页首显示一次，不再同时列出相同的起止日期。

课程使用宽卡片依次排列，左侧分别标明每张卡的起止时间，右侧依次显示课程名、带标签的地点和教师。时间相交的不同展示课程仍各占一张卡。通过 `todayPeriod` 划分上午、下午和晚上，仅显示有课的时段；空日显示“无课程”。

日页复用 `todayReferenceDuration`、`TodayAgendaScale` 与 `todayAgendaHeights`，依据学期作息、课程时长和文字所需高度安排卡片。较长课程保持更高的卡片，课程之间的空闲时间不额外拉开间距。

## 周、月与学期页：周网格

周页固定使用七个等宽日期列和左侧时间轴。月页将周课表按两列拼贴；学期页在超过六周时使用三列，否则使用两列，实际列数不超过周课表数量。每个选中月份或学期仍占一页，同行的星期列保持对齐。

网格复用 `timetableGroups`，将时间范围相交的展示课程合成一组，组卡覆盖该组的完整时间跨度。标准节次组的课程名、地点与教师分别去重，用 ` / ` 联结，地点显示在教师之前。列宽固定，重叠安排通过分组展示；组内实际发生的重叠安排显示冲突数量，非本周或休假记录不会单独形成实际授课冲突。

有课程的周网格在左轴依次显示节次号、该节开始时间和结束时间，横线仅绘于节次开始位置。`protectedSpans` 为每个节次预留三行标签的空间，当前最低高度为 76 个画布单位；某节没有课程时仍保留标签，整周无课程时显示空态。

`ExportTimeline.pagePositions` 同时测量一页内全部周网格，先满足分组卡片的文字高度和节次标签空间，再校正时间轴。严格时长排序只比较课程 `spans`，使同页较长的展示课程跨度严格高于较短跨度，并保留至少一个像素的高度差；节次 `protectedSpans` 不作为课程参与排序。卡片时间区间由 `y(end) - y(start)` 决定，区间内保留固定块间距。算法在可读性约束方案和统一比例方案中选择更紧凑的画布，未被课程或节次标签保护的空档可压缩。

标准节次课程的起止时间由左轴标签表达。若组内任一展示课程的开始或结束时间无法对应作息标签，则在主卡标题之后补充该组全部课程的起止时间，按标题对应的课程顺序排列，保留重复时段。此时课程标题也保留同名条目，使每个标题与时段逐项对应；地点与教师仍使用去重摘要。日页和网格正文都按固定字号完整换行，优先使用自然词边界，超宽单词按 Unicode 字形边界折行。长内容通过增长画布容纳。

## 待排课程与数据文件

明确列出周次但尚未安排时间的课程以 `Lesson.unscheduled` 保存。每页按涉及的教学周统计相交的源授课记录，数量大于零时在页首显示摘要；统计单位为授课记录，而非去重后的课程名称。待排记录不进入日期网格，也不另列教师、地点或周次清单。

JSON 数据文件继续使用 `PlanCodec` 导出当前方案的名称、全部课程及源授课记录，包括待排安排、周次、日期、时间、教师、地点、备注、学分和课程附加字段。凭据类附加字段沿用现有过滤规则。数据文件不受可视化导出的日期范围或代表卡片投影影响，可重新导入；学期设置与多学期页面选择不属于该文件内容。

## 主题与语言

背景、正文、次要文字、时间轴和休假阴影取自 `cridColorScheme`。浅色与深色模式遵循 `request.settings.theme`；跟随系统模式使用导出上下文的当前系统主题。课程颜色通过 `CourseColors.swatch` 结合主题背景计算。普通课程无边框，非本周组卡使用更淡填充与彩色虚线，休假日期和组卡带斜线阴影；网格保留非本周、休假和调休等文字摘要。

周网格中的当前日期使用主题 `primary` 圆形底色与 `onPrimary` 文字。`Document.today` 在页面布局完成、文档创建时固定，之后各页与流式条带沿用同一日期，绘制过程不再读取时钟。

PNG 与 PDF 使用相同调色方案，输出为标准 sRGB 色值。界面在支持设备上的 Display P3 窗口缓冲不参与文件导出。

生成的日期、周次及状态标签跟随 `request.settings.language`，七种预置官方节假日名称也使用对应语言。课程名称和用户填写的授课信息保持原文。PNG 与 PDF 共用这些文本和样式。

## 文件与资源

`estimate(request)` 和 `estimate(requests)` 与实际导出共用页面测量，页数等于所选日历单位数。单位内部的图表不拆成续页，PNG 倍率也不改变页数。测量发现图片过大时，在写文件前提示降低分辨率或选择 PDF。

用户通过系统目录选择器提供 SAF tree Uri。PDF 输出一个文件，按所选单位顺序写入各页；PNG 每页输出一个带三位页码的文件。单方案文件名保留方案名，多学期文件使用 Crid Next 前缀，并附起止范围。应用创建新文件，同名处理由文档提供方完成。

导出在 `Dispatchers.IO` 运行，页面测量通过检查点响应取消。PDF 逐页绘制并在结束时关闭文档；PNG 在绘制每个条带前、编码每 32 行时检查取消状态。

最终画面不超过 2400 万像素的 PNG 使用整页 Bitmap 编码。更大的页面按条带光栅化，每个条带最多编码 128 行，上下各增加 4 行保护缓冲，使圆角抗锯齿远离条带裁剪边缘。先从 `BAND_PIXELS` 的 1,048,576 像素预算扣除保护行，再确定条带正文高度；缓冲参与光栅化，但只编码中间的实际图像行。条带位图总占用仍不超过约 4 MiB，另有行缓存和压缩缓冲。

`StreamingPng` 将各行写入同一个 Deflate 压缩流，再分成多个 PNG IDAT 块，最终仍输出一个完整 RGBA PNG 文件；保护行不会改变文件尺寸、页数、字号或绘制坐标。

每张 PNG 在应用分辨率倍率后最多包含 1.92 亿像素，宽度不超过 16,384 像素，高度不超过 65,535 像素。超过任一限制时，预估阶段提示降低分辨率或选择 PDF。单个请求的日期范围最多 732 天，一次输出最多 750 页。

写入失败或取消后，导出器尝试删除本次已经创建的文件。清理失败保留最初错误，文件提供方负责目录权限、剩余空间与删除能力。

## 验证

2.0.0 沿用 1.16.1 的导出契约。对应功能实测结果与本地记录位置见 [1.16.1 验证记录](迭代验证-1.16.1.md)，公开发行文件见 [2.0.0 发行说明](releases/v2.0.0.md)。历史记录中的 `artifacts/` 是开发时的本地目录，不随公开源码提供。

`ExportUnitsTest` 覆盖日历单位数量、周起始日和学期边缘，并检查时间轴上的严格时长顺序。设备回归使用 `ExportInstrumentedTest` 调用真实 Android Canvas、PNG 编码器与 PdfDocument，通过测试 SAF 提供方输出文件；生产包不包含该测试提供方。

设备验收项目包括每个单位恰好一页、多学期页序、日程分时段、周网格分组、节次标签、自定义时段对应、地点与教师顺序、长文字完整换行、页首待排数量和浅深主题。PNG 与 PDF 逐页比较尺寸和内容，并提取 PDF 文本检查图表摘要及确认页底列表已移除；真实课表同时检查跨周投影、连续节次、边框规则、语言设置及图片资源预算。流式与整页 PNG 对比条带边界和当前日期标记，完整源数据保留通过 JSON 往返校验；执行结果记录在上述 1.16.1 功能验证中。

历史验证见 [初始验证记录](验证记录.md)、[1.2.0 迭代验证](迭代验证-1.2.md)、[1.3.0 迭代验证](迭代验证-1.3.md) 与 [1.4.0 迭代验证](迭代验证-1.4.md)。按内容拆页、独立重叠列道和页底完整记录等结果对应各自版本的导出契约。

可单独运行导出设备测试：

```powershell
adb shell am instrument -w -e class cn.crid.next.export.ExportInstrumentedTest cn.crid.next.test/androidx.test.runner.AndroidJUnitRunner
```

需要保留审查产物时，在卸载测试应用前取回设备上的 `export-validation` 目录。Gradle UTP 的测试清理可能删除应用及其外部文件，具体取回路径见对应迭代记录。
