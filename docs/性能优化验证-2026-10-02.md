# 性能优化验证 · 2026-10-02

> 历史验证记录：本文描述当时的版本与检查结果。当前版本见 [README](../README.md) 和 [更新日志](../CHANGELOG.md)。`artifacts/`、`tools/local/` 路径及旧提交号属于未公开的本地开发记录。

优化前恢复点为 `d2b0fe3`。本轮保留课程管理、导入导出、提醒、小组件、动画、配色和排版。原生能力达到相同或更好效果及性能时优先采用；有明确优势的自定义实现保留。本次采用的 Android / Compose API 可在现有最低版本 Android 12 上运行。

## 实现

- 排课在一个输入快照内建立星期、固定日期和作息索引。周视图、今日后续课程、小组件、提醒与导出复用索引；单日入口保留学期外提前返回，仅准备当日相关记录，与批量索引共用日期和调休逻辑。
- 课程合并复用规范化名称、代表记录和周次，通过授课上下文及同课程索引缩小候选范围。导入冲突检查提前解析字段，保留原有比较上限与告警。
- 小组件在一次刷新中跨实例、尺寸共享每日课程。提醒快照直接采用排课结果，避免按每个提醒时间重新排课。
- 高亮状态交给 Compose `drawWithCache` 观察，只触发绘制。静态虚线描边使用 `remember` 复用；动画仍使用原生 `animateFloatAsState`、`AnimatedContent` 和原有弹簧参数。
- 今日课程测量使用原生 `TextMeasurer` 缓存，随字体和密度变化更新。复用语言对象与日期格式器，文字视觉居中只量测首尾可见行。
- 导出在单个文档内缓存相同文字的换行结果，复用原生 Paint、Typeface 和 DashPathEffect；分带 PNG 通过 Canvas.quickReject 跳过不可见课程卡。
- 合并三处重复课程背景绘制，移除已被 TodayAgenda 替代的旧今日网格分支、未使用的私有文案和三个无调用依赖。有效但未改变的数据不再写盘或触发平台刷新。

## 可复现计算基准

使用 [benchmark 工具](../tools/performance/README.md) 分别导出 Git 基线与当前源码，独立编译后运行相同的确定性数据。每版 3 个独立 JVM，每项预热 8 次，每个 JVM 记录 9 个批量样本；下表采用 27 个样本的中位数。索引建立包含在排课计时内。

| 运算 | 优化前 | 优化后 | 耗时下降 | 临时对象分配下降 |
| --- | ---: | ---: | ---: | ---: |
| 112 天、500 门课程、3,000 条安排的排课 | 82.45 ms | 3.34 ms | 95.95% | 95.71% |
| 112 天的课程卡片合并 | 61.60 ms | 10.51 ms | 82.94% | 87.71% |
| 合并导入与冲突检查 | 44.29 ms | 5.87 ms | 86.74% | 94.18% |
| 64 个提醒时间的完整快照 | 10.58 ms | 2.88 ms | 72.82% | 80.53% |
| 3,000 条安排中的单日查询 | 0.737 ms | 0.184 ms | 75.00% | 84.59% |

四项批量输出及额外 128 组随机卡片合并案例的 SHA-256 均与基线相同，包含顺序、源授课记录、代表课程、冲突告警和提醒内容。单日查询单独核对完整输出，并增加预热和批量次数。最终原始样本、源码哈希和运行环境位于 批量运算记录（`artifacts/performance-2026-10-02/final/`） 与 单日查询记录（`artifacts/performance-2026-10-02/single-day-final/`）。这些数字描述桌面 JVM 上的计算耗时；分配量是每次运算产生的临时对象总量。

最初的单日实测发现约 9% 回退，改为只准备当天记录后得到表中结果；另有 144 组设置组合验证单日查询与完整索引的输出一致。学期外提前返回保留原有策略，此次采样为 84 / 97 ns、均分配 456 B，不宣称这一路径加速。

## 设备与构建验证

使用独立 Android 12 / API 31、x86_64 模拟器，720×1600、320 dpi、软件 GPU。测试使用合成课表，不连接教务账号。普通周视图截图排除系统栏后比较 1,051,200 个像素，优化前后相同。

帧统计采用同一课表的切周及四个页面切换，每版执行三遍，原始 gfxinfo 与 framestats 保存在性能记录目录。构建及图像测试后的采集曾出现异常卡顿；停止驻留内存超过 6 GB 的构建进程并重启模拟器后，该异常消失。受控复测的 P95 为基线 20–38 ms、优化版 26–34 ms，累计 jank 比例约 8.1% / 9.6%。这组 Debug / 软件 GPU 数据不能确认整体帧率提升，两个版本都有明显波动。绘制回归直接验证高亮像素变化及课程内容不发生额外重组。

Debug、Release 和 R8 构建成功。177 项核心 JVM 测试、219 项应用 JVM 测试全部通过，应用测试在 Debug / Release 两种构建下均通过。六份原始课表样例的逐字段回归保持通过。lint 为 0 错误、57 条警告、1 条提示，与优化前记录一致。

最终 85 项设备回归全部通过，覆盖导航手势、对话框与底部面板动画、高亮绘制、字形居中、今日与周课表、课程详情、响应式小组件、提醒送达及四种导出粒度。流式 PNG 在 1× / 2× 分辨率下与整图输出比较，接缝检查通过。

单日查询的最后修正经过上述 JVM 测试及独立基准核验后，再用最终 APK 复跑 12 项提醒测试和 1 项原生绘制缓存测试，13 项全部通过。专用模拟器已关闭。

首次设备回归暴露出提醒测试的人工快照注入与异步刷新的竞争：测试直接写设备存储，未遵守生产调度器的同步约定。测试现在在同一 monitor 内写入、校验并投递，通知隐私、送达、去重与旧历史迁移断言均保留；最终完整提醒测试通过。生产提醒锁与系统注册策略保持原有实现。

Release 保留四种架构。本轮仅生成本地未签名验证包，版本号未变，也未覆盖正式发行文件。压缩内容体积与基线基本相同；性能收益主要来自重复计算和临时分配减少。
