# 课程提醒送达设计

1.13.0 在原有准时提醒基础上增加可选的闹钟级提醒，并支持重启后首次解锁前恢复已安排的通知。提醒只由真实课程触发，声音与振动遵循系统通知通道及免打扰设置。

## 调度方式

普通模式使用允许设备闲置时执行的精确闹钟。闹钟级模式使用 `setAlarmClock`；Android 将其视为时间要求更高、对用户可见的闹钟，必要时退出低功耗状态。应用明确告知用户系统可能显示闹钟标记，点击系统的下一闹钟入口可回到今天页。两种模式均检查准时提醒授权，无授权时使用系统允许的非精确调度，并在状态页提示可能延迟。[Android 闹钟指南](https://developer.android.com/develop/background-work/services/alarms#exact-alarm)

提醒最多提前登记 64 个独立触发时间，同一时刻的课程共用一次唤醒。后续提醒不依赖上一条成功触发；六小时后台维护用于核对安排，不承担精确计时。提醒发送前校验当前课程，结束后的课程不补发；同一课程实例使用稳定身份去重。

## 重启后首次解锁前

Direct Boot 允许提醒类功能在设备完成启动、用户尚未首次解锁时工作。此时完整课表与凭据所在的用户加密存储不可访问，专用接收器只读取设备加密存储中的必要提醒快照。[Direct Boot 指南](https://developer.android.com/privacy-and-security/direct-boot)

快照保存已安排提醒的时间、通知内容及稳定身份，不复制完整课表或服务凭据。关闭提醒、删除课程及切换方案后，旧快照必须失效。锁定期间只恢复和发送有效课程提醒，不初始化课表仓库、后台任务或小组件；解锁后重新按当前课表核对，并沿用送达记录防止重复通知。

## 厂商设置

设置主页提供“上课前提醒”和“提前分钟数”。二级“提醒设置”提供闹钟级模式，以及 Android 公开的通知、准时提醒、电池优化和应用设置入口；提醒关闭时仍可查看系统状态。应用不自行授予电池豁免，也不调用厂商私有页面。部分设备还需要用户在系统中允许自启动或后台活动，以下路径来自厂商公开说明，具体名称可能随机型与系统版本变化。

## 送达边界

后台限制可能影响闹钟、任务及开机广播。用户强行停止应用后，系统会取消其待执行操作；再次打开应用才能重新安排。应用尊重这些系统限制，不使用隐藏窗口、伪装前台服务、无声播放或持续唤醒锁。[Android 后台限制](https://developer.android.com/topic/performance/background-optimization)、[强行停止行为](https://developer.android.com/about/versions/15/behavior-changes-all#stopped-state)

模拟器用于验证系统休眠、重启恢复、权限变化及通知去重。国产设备的实际送达表现仍需在对应机型和后台策略下核对。
