# 课表解析验证

本实现从零读取测试文件。BIFF 用独立的 Python xlrd 检查原始单元格，HTML 用 BeautifulSoup 检查课程块及星期列；逐字段预期保存在 `tests/expected/`，运行时解析器不读取这些预期文件，也未参考旧项目实现。固定 SHA-256 用于识别测试源变动。

2026-10-06 已将真实样例替换为匿名等价版本，本页涉及的身份信息同步使用合成值。原有时间安排和验证场景保持，迁移范围与等价检查见 [测试样例说明](../tests/README.md)。

### Python 连续课程的显示修复（1.3.0）

秋季源文件中的 `Python合成课甲` 从解析、导入到持久化始终是一门 `Course`，含第 5–6 节和第 7 节两条 `Lesson`。两条记录均为第 1–16 周、星期三，教师为示例盈，地点为样甲楼C203(140)。此前的两张课程卡来自显示层按不同起止时间分别绘制，不是解析器把课程分成了两门。

`displayCourses` 现在将同一授课上下文中的相邻节次合为一张显示卡。在该学期作息下，第 5–6 节 `13:30–15:10` 与第 7 节 `15:30–16:15` 显示为 `13:30–16:15`，包含内部课间。课程的两条源记录继续保留；不同教师、地点、周次或状态，以及跳节和仅钟点接近的安排不会据此合并。该修复不更改解析预期或已有保存数据，无需重新导入。

`TimetableParserTest` 新增对课程身份、两条源记录、首次导入及重复合并导入的断言；`DisplayCourseTest` 另检查连续卡片的起止跨度和源记录保留。导出明细只读取原始两条记录，不把显示跨度再作为第三条安排。测试执行状态见 [1.3.0 迭代验证](迭代验证-1.3.md)。

两种模板的时间记录数量相同，但内容并非完全相同。按照用户确认的名单顺序，列表中的教师与原始授课周段依次对应，在分拆离散节次之前完成绑定。如果多个星期共享同一周段且教师数恰好等于不同周段数，则按周段首次出现顺序绑定，同一周段复用同一教师。单个教师应用于该课程全部记录。网格为每个课程块提供具体教师，分别保留。网格没有学分，全部留空，不能从另一文件补填。

并非所有列表的教师数都与周段数一致。直接核对原单元格可见：合成课辛BⅡ有2位教师、3种不同周段（第1周、第1–16周、第2–16周）；合成教育案例与实践有5位教师、第9–15周共7段；合成安全导论有6位教师、第9–15周共7段。源文件无法唯一确定重复授课教师的位置，因此完整名单保留在 `extra["教师名单"]`，各条记录的教师留空并提示待确认；时间记录仍全部导入。不把全名单重复写进每条授课记录，也不从其他文件猜补。

关键预期如下：

- `10-12周(双)`和 `10-12双周`都表示第10、12周；第13和14周的不同教师记录独立保留。
- 合成课课子3：第10、12、14、16周依次对应示壬、示例月、示例收、示例日，不能让每周都显示4名教师。
- 合成语言听说：网格第1–8周教师为 `SYNTHETIC TEACHER ALFA`，第9–15周为教师丙。
- 同名课程的列表教师顺序是 `教师丙;SYNTHETIC TEACHER ALFA`，按该列表原顺序绑定第1–8周和第9–15周；不能用另一份网格覆盖列表中的顺序。
- 体能(入门)：第1周与第2–15周地点不同，两条记录保留。
- 合成理论：星期六和星期日各有第1–4节及第5–8节，共4条；另有第11周待排时间记录，完整导入共5条，不能当作已知安排的重复项删除。
- 合成心理Ⅱ：第7–14周只有周次，没有星期和节次；课程保留1条待排时间记录，并保留教师壬和原说明。
- HTML 网格的 `rowspan` / `colspan` 用于恢复真实星期列，不根据当前行单元格数量猜星期；“选课”按钮不是地点或课程备注。

## 导入与错误行为

`TimetableParser.parse(bytes, filename)`返回 `ParseResult`。文件损坏、格式或模板未适配、课程名缺失、周次或节次无效会进入 `errors`。缺失教师、地点、学分时留空并进入 `warnings`。明确给出有效周次且星期和节次都留空的项目成为待排时间记录，进入 `warnings`，允许完整导入。六份给定样例均应满足 `valid == true`、`errors` 和 `unresolved` 为空。

如果整个时间字段缺失，或只写星期却漏掉节次、只写节次却漏掉星期，仍进入 `unresolved` 并保留原说明，不擅自解释为完整待排记录。待排记录的周次同样严格校验，`0周 []` 和 `4-2周 []` 都应报错。未知或无效源内容不会通过放宽校验而静默消失。

课程名使用统一 `courseKey` 归类，但教师、地点、时间不同的授课记录均保留。程序化解析本身不删除完全重复的源记录，后续合并规则负责提供去重预览。

本地解析不会执行公式、宏、脚本或外部实体。XLSX 公式单元格要求先转换为值。文件上限15 MB、ZIP 解压总量64 MB、ZIP项目256、工作表单元格200,000，避免无界解析。

在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File tools/build.ps1 -Task :core:test
```
